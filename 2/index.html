Project 2: Fun with Filters and Frequencies

Convolution From Scratch

To implement convolution using four for loops, I first had to determine the values that we would be looping over. As convolution involves computing the weighted sum of a specific region, the values used within the loops would be the height and width of both the kernel and the image, with the image dimensions more specifically making up the outer loop. From there, we flip the kernel and then move it across the image, totaling up the overlapping areas in order to calculate the corresponding coordinates of the output matrix.

To handle the boundaries of the convolution, we use np.pad() to pad the image with 0s. For each side, the pad size is equal to half the kernel size as that's the maximum distance out necessary to properly run the convolution.

Handling the padding this way also helps with the looping as it allows the center of the kernel to be img_y + k_y and img_x + k_x, meaning that we don't need any special logic to make sure that the weighted sum is properly calculated.

For the two-loop implementation, the only major difference was that instead of the two internal loops, they were replaced with one matrix multiplication and its summation. 


            # Part 1.1: Four For Loop Convolution
            def convolve_four_loop(kernel, image):
                k_h, k_w = kernel.shape
                img_h, img_w = image.shape
                flipped_kernel = np.flip(kernel)
                h_pad = k_h // 2
                w_pad = k_w // 2
                padded_img = np.pad(image, ((h_pad, h_pad), (w_pad, w_pad)))

                result = np.zeros((img_h, img_w))
                for img_y in range(0, img_h):
                    for img_x in range(0, img_w):

                        total = 0
                        for k_y in range(0, k_h):
                            for k_x in range(0, k_w):
                                total += padded_img[img_y + k_y, img_x + k_x] * flipped_kernel[k_y, k_x]
                        result[img_y, img_x] = total

                return result
                        

            # Part 1.1: Two For Loop Convolution
            def convolve_two_loop(kernel, image):
                k_h, k_w = kernel.shape
                img_h, img_w = image.shape
                flipped_kernel = np.flip(kernel)
                h_pad = k_h // 2
                w_pad = k_w // 2
                padded_img = np.pad(image, ((h_pad, h_pad), (w_pad, w_pad)))

                result = np.zeros((img_h, img_w))
                for img_y in range(0, img_h):
                    for img_x in range(0, img_w):

                        result[img_y, img_x] = np.sum(padded_img[img_y:img_y + k_h, img_x:img_x + k_w] * flipped_kernel)

                return result

When comparing both loop implementation with scipy.signal.convolve2d, there was no difference between them when it came to the result. Both the four and two loop implementation properly convolved the selfie with 9x9 Box filter and the finite difference operators

However, the custom implementation and convolve2d did differ when it came to runtime. For instance, convolve2d averaged 8 seconds with the box filter, the four loop box filter averaged 90 seconds, and the two loop box filter averaged 20 seconds. This pattern continued with the finite difference operators, though much faster across the board due to their smaller dimensions.

Gradient Magnitude and Edge Images

Using the finite difference operators, we are also able to compute an image's gradient magnitude and later the edge image. For the gradient magnitude, we first convolve the original image with both finite difference operators. This gives us the differences in both dimensions that we can use to calculate the magnitude via np.sqrt(cameraman_Dx ** 2 + cameraman_Dy ** 2). The resulting image shows both differences combined, highlighting the high frequency areas.

To emphasize the high frequency areas even more, we can transform it into an edge image by binarizing each pixel based on a selected threshold.

The threshold chosen for this image is 0.23. With any lower threshold, too many background pixels would light up. If the threshold were 0.25 or higher parts of the cameraman would begin to disappear.

Derivative of Gaussian (DoG) Filter

Even with our specific threshold, there is still a large amount of noise present within the edge image. To fix this, we can convolve our finite difference operators with a version of our cameraman that was already convolved with a gaussian filter. This smooths out a lot of the background noise, allowing our finite difference operators to just pick up on the cameraman.

In the pictures above, the effect of the gaussians can be seen, primarily near the bottom of the images where most of the noise is located. In the image with the gaussian, basically all of the noise is gone. However, the cameraman's outline is still present and mostly intact.

To simplify this process, we can create Derivative of Gaussian (DoG) filters, allowing us to only have to perform one convolution with our target image. These filters are created by convolving our gaussian with the finite difference operators.

Using our DoG filters, we are able to end up with the same image using only one convolution.

Image "Sharpening"

Beyond just using gaussian filters to smooth out our images, we can also use them to sharpen our blurry images. To do this, we will first convolve our blurry image with the gaussian. The gaussian acts as a low-pass filter, meaning that we end up with just the low frequencies of our image.

By then subtracting our original images with their low frequency counterpart, we end up with just our high frequency images.

If we add these high frequencies back to the original image, we can "sharpen" them, making the edges pop out more.

For the images above, their high frequency versions are added with a 1x multiplier. We then get ultra sharpened images if we up this multiplier.

To demonstrate the sharpening one more time, we can even intentionally blur an image and then try to resharpen it back.

While not all of the original details have been returned, the sharpened dog contains substantially more detail than the original blurred one.

One last key detail about this section is that, unlike the previous images who were normalized in order to be properly displayed, the sharpened images were rather clipped between 0 and 1 using np.clip(). While this doesn't change anything mathematically, it does make transformations like sharpening easier to see.

Hybrid Images

With frequency transformations, we can also use them to combine two images into one hybrid image.

To start, we first have to align our two images. Even though the alignment doesn't change any of the frequency transformations, it does help the hybrid illusion out as properly aligned images make both images much easier to see.

Now that we know the proper alignment of the images, we can pass one image through a high pass filter (the cat), and the other through a low pass filter (the lion). In terms of the cutoff frequencies, I chose sigma of 5 and 7 respectively for the cat and lion. I found a sigma around 6 to be best for images their size. Moreover, the High-pass image has a slightly higher sigma as it makes it easier to see when ontop of the low pass image.

With both high pass and low pass images, we can add them together to get our hybrid image.

Gaussian and Laplacian Stacks

Another technique we can do with frequency transformation is blending two images together. But to do this, first we need to create Gaussian and Laplacian stacks of our images.

To get the Gaussian Stack, we repeatedly convolve our image with a gaussian filter. In order for each level of the stack to be constantly blurred enough, the Sigma is set to 2 ** i, where i is the level of the stack. With the Gaussian, the Laplacian stack can be calculated by subtracting neighboring layers of the gaussian stack.

Finally, we also create a gaussian stack for our mask, which for our Oraple, will be one with a vertical seam.

Multiresolution Blending

With the Laplacian Stacks and the Gaussian stack of the mask, we can recreate the Oraple. More specifically, for each layer of the laplacian stacks, we will take the respective layer of the mask's gaussian stack and use all three images to create the layer's blended image. 


        masked_im1 = gaussian_mask[i] * laplacian_im1[i]
        masked_im2 = (1 - gaussian_mask[i]) * laplacian_im2[i]
        blended_level = masked_im1 + masked_im2

Afterwards, all of the blended levels are summed up together, resulting in the multiresolution final blend.
